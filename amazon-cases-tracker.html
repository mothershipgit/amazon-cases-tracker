Instructions

At the top you will find the main KPIs providing an overview of this part of the operational activity on Amazon.

Below that, there is a static section containing basic information about the team's current workload.

Further down there is an accordion section presenting the core data for:

  1. Total Cases — both open and closed cases combined.
  2. Open Cases — the same set of charts, but only for cases that are currently open.
  3. Closed Cases — the same set of three charts, but only for cases that have already been closed.

At the bottom there is a table with filters, where data can be filtered by brand and by marketplace.

Close & Status

In the first column, Close, we mark the moment when a case is finished — either successfully or unsuccessfully.

In the Status column, the following three statuses should be used before moving a case to the closed table:

  • Resolved
  • Not Resolved
  • On Hold

The statuses Waiting on Us and Waiting on Amazon should only be used while the case remains in the upper table (open cases).

Once Close is selected and a final status is assigned, the case will automatically move to the bottom table containing closed cases.

If a mistake is made and the case needs to be restored, simply uncheck Close in the bottom table, and the case will return to the open cases list.

Table Columns

The table contains columns that identify and describe each case.

Issue Type is assigned automatically based on AI analysis of the email content. We will monitor how well this works in practice. If too many different issue types are generated, we will introduce a dropdown with a predefined list, which will then be maintained manually.

The Status column is filled in manually.

The Summary column is generated by AI and provides a short, high-level summary of the case.

There are also two additional columns:

  • Next Action
  • Notes

These fields are intended for manual input by the person responsible for the case. It is recommended that the person managing the case updates these fields after completing work on the case, for example at the end of the day. This allows any team member to quickly understand the current status of the case and the next steps.

Messages & Days Open

At the end of the table there are columns showing the number of messages exchanged and the number of days the case has been open.

For Issue Type: Premium Support, the number of messages and days may be high because this case is kept open all the time. It is excluded from the statistics and charts displayed above the table.

Parent Cases (Linking Related Cases)

An additional feature has been introduced to handle situations where one issue generates multiple Amazon cases. This often happens when, after a few days, Amazon requests an appeal, which is created under a new case. As a result, a single problem may end up having two, three, or sometimes even four related cases.

Every case contains a "+" button in the Parent column.

When a second case appears for the same issue:

  • Click the + icon in the Parent column next to the second case and enter the Case ID of the original (first) case.
  • The recommendation is that the parent should always be the first case that was created.

Once the cases are linked, they will appear grouped together in one block, one below the other. The background will turn green, making it easier to identify related cases.

Within such a block, sorting (brand, market, owner, opened, last update, etc.) is based on the parent case, not on the cases that were opened later.

If you want to remove a parent-child connection, simply remove the Parent Case ID from the Parent column in the relevant child case row, then click away.

Case ID Details

In the Case ID column, some cases display a small number, for example "6". This indicates how many messages have been exchanged between us and Amazon within that case.

Another important element is the triangle icon ▶. When clicked, it displays the case history, including:

  • Message dates
  • The issue type
  • A short summary of each message received from Amazon

The summaries may not always be perfect, but they provide a quick timeline of events for the case.

New Email Indicator ✉

When new emails arrive for a case (after clicking Refresh), a pulsing red ✉ envelope icon appears next to the Case ID.

  • The envelope means this case has received a new email that you haven't reviewed yet.
  • Click the envelope to acknowledge it — the icon disappears, confirming you've seen the update.
  • Each user has their own acknowledgment state — Tom acknowledging does not affect Vitali's view, and vice versa.
  • On page reload, envelopes reappear for any case where a new email arrived after your last acknowledgment.
